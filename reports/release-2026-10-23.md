# Release 2026-10-23: production configuration decision

Production generates with Cloudflare `@cf/meta/llama-3.1-8b-instruct-fast`. This release adds
the document graph (migration 006, prompt `support-v5`, 29 documents, 12 edges), so expansion
was evaluated with the production generator before it was enabled.

Setup:
- Local pgserver database with Cloudflare `bge-small` embeddings, the same manifest as
  production.
- 48 cases, 38 of them model generations.
- Each configuration ran once, at temperature 0.

| Generator | Graph expansion | End-to-end | Development split | Schema valid | Citations valid | p50 / p95 |
| --- | --- | --- | --- | --- | --- | --- |
| Cloudflare Llama 3.1 8B | off | 0.763 | 15/20 | 0.921 | 0.921 | 1.8 s / 4.7 s |
| **Cloudflare Llama 3.1 8B** | **on** | **0.763** | **16/20** | **0.974** | 0.921 | **1.6 s / 3.9 s** |
| Fine-tuned Gemma 4 12B Q4_0 | off | 0.868 | 18/20 | 1.000 | 0.974 | 7.4 s / 10.4 s |
| Fine-tuned Gemma 4 12B Q4_0 | on | 0.842 | 17/20 | 1.000 | 0.947 | 5.7 s / 11.1 s |

**Decision: `GRAPH_EXPANSION=true` in production.** The choice uses the development split, as
in `reports/graph-expansion.md`, where expansion is one case better (16/20 vs 15/20). The
overall pass rate is tied. Schema validity and tail latency also improve.

Cloudflare with expansion:
- **Fixed:** `obsolete-vs-current-2`, `credential-rotate-1`, and `injection-user-2`.
- **Regressed:** `retry-recovery-1` (the same RRF reorder the graph report describes),
  `injection-source-1`, and `replay-retention-1`.
- **Still failing:** both sandbox conflict cases. Llama 8B picks one number even when the
  conflict relation is shown; base Gemma 4 12B abstains (see the graph report).

The fine-tuned model was trained on `support-v4` and has never seen relation lines. Expansion
costs it one case, and it does not solve the conflicts either. Retraining with `support-v5`
prompts that include relations is the next step for the self-hosted path. Its published
`support-v4` results stay as reported in `model-comparison.md`.

Production steps for this release:
1. Ran migration 006 and live ingestion of the 5 new documents against the production Neon
   project from local maintenance (`--allow-production`, provider smoke receipt). The result is
   29 live chunks and 12 edges, and the runtime role has read-only access to edges.
2. Set `GRAPH_EXPANSION=true` on the production API.
3. Merged into master.

Raw reports: `release-cloudflare-graph-{false,true}` and `release-finetuned-graph-{false,true}`
(`.json` and `.md`).
